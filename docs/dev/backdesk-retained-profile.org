#+TITLE: Retained publication receipts

Env keeps ordinary variable values and generation counters in native ETS terms.
Compiler-produced publication receipts use a versioned, bounded representation:

- Version 3 carries an ETF binary containing the complete version-2 receipt.
- =BeamLisp.Env/emitted_definition_data= materializes receipt data for inspection.
- The decoder checks the envelope, byte budget and compressed-size header before
  safe decoding. Oversized ordinary definitions retain their legacy form.
- Publication readers validate inert data before and after materialization, then
  bind declarations and execution descriptors to actual loaded code.
- Checked snapshots retain the exact stored receipt. Private cache observations
  compare that row, actual bindings, code identities and generation fences.

Receipt data supply no execution authority. A changed or opaque payload must
pass the same independent publication checks as every other representation.
Normal variable lookups need no receipt decoding.

Run the focused publication, native-proof-cache, inert-inspection and emission
suites against one immutable SDK. Include corruption inside an encoded payload,
raw row replacement without an epoch, oversized headers and retired definitions.
Use actual table/binary accounting for storage measurements; an expanded term's
flat size describes materialization cost rather than compact resident storage.

Application startup measurements use a fresh synthetic store and omit provider
credentials. Measure the entire process through readiness: verification and
library preloading happen before an entry program's own timer starts. Application
packages enter through =bl serve= and its loading policy. =bl run= executes a
program directly.

Execution-graph memberships use a module-keyed map in the protected native
extent table. Both graph publication and unpublished retirement populate the
map together with the exact per-scope rows, inside the private owner turn and
physical module fences. A lookup checks each selected entry against its exact
row. Closing a graph retains its membership records while existing pins drain;
indexing never substitutes for code identity, graph closure or lease checks.
A module with no memberships requires a native key lookup rather than a scan
of unrelated SDK bindings and extents. Capacity estimates include index keys.

Serving entries return after starting their listeners and managed workers.
=bl serve= unwinds the program call, collects its caller's transient startup
heap once, then owns the foreground wait. Putting an infinite sleep inside the
entry prevents this boundary. Verify HTTP responses after the entry returns,
including handlers with managed callbacks. Qualify child test VMs against the
same exact SDK using =BL_QUALIFY_CANDIDATE= when a suite supports that override.
