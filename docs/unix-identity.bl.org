#+title: Kernel Unix identity and the existing principal context

The new =auth.unix= library is under SDK qualification. It is a trusted host
adapter; supervised listener and cross-user integration are still unfinished.

#+begin_src clojure
(require '[auth.unix :as unix] '[auth.identity :as identity] '[datom :as d])

(unix/with-peer! accepted-socket "messages"
 (fn [uid]
  (let [account (d/entity (d/db directory) [:account/unix-uid uid])]
   (when account
    {:subject (:account/principal account) :kind (:account/kind account)})))
 #(messages/inbox workspace))
#+end_src

=directory= is the existing host-owned account connection. The example's indexed
UID and principal attributes belong to that application's schema; the adapter
does not impose another database. Resolve current rows per invocation. Existing
role providers remain authoritative; the resolver returns subject and kind only.
The application comes from host configuration.

=peer!= reads Linux SO_PEERCRED from the connected socket, using kernel PID/UID/GID.
PID is diagnostic. Payload fields cannot select that identity. Unknown accounts
deny, and application Source cannot invoke the host constructor. The existing
verified context and its executable lifetime restore on success or exception.
An inherited person is cleared while resolving the new connection's account.

This consumes an already accepted inet-backend Unix socket. It does not bind or
reclaim endpoints, supervise connections, or grant permissions from filesystem
ownership alone. Those operations compose with existing endpoint leases,
native supervision, framing budgets and namespace authorization in the next gate.
