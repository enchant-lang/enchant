#+title: Bounded native data on local RPC

The new =data.first-order/encode!= and =decode!= API is under SDK qualification.
It reuses the existing compiler-owned closed ETF validator. No parser, schema
engine or runtime-object deserializer is added.

#+begin_src clojure
(require '[data.first-order :as data])

(data/encode! {:namespace "messages" :operation "inbox" :args ["work"]}
              {:max-bytes 65536})
(data/decode! frame {:max-bytes 65536 :max-nodes 4096 :max-depth 32})
#+end_src

Values stay native maps, vectors, sets, symbols, numbers and strings, ready for
Datom transactions or queries. Encoding validates data before serialization;
there is no diagnostic printer, lazy forcing or callback dispatch. The output
is uncompressed ETF with a checked byte limit.

Decoding checks the frame bound, then the existing raw ETF tag/structure budget
before calling the BIF. Compression, trailing bytes, functions, PIDs, ports and
references refuse before runtime objects are allocated. Safe atom decoding
refuses unknown atoms; load the receiving contract and Datom schema first.
The caller's first-order logical budgets are then checked on the decoded value.
Raw wire structure also retains the validator's fixed default limits.

This is a data codec, not an authority or RPC protocol. A service still owns
framing, protocol/schema version, principal resolution, exported operation
checks and its accepted-work lifetime. Verified identity evidence and runtime
handles deliberately cannot pass through it. EDN remains the readable one-time
SQLite export/import format; the local native path avoids text conversion.
