#+title: Native data through authorized namespace imports

Local =auth.interface= calls and ordinary imports validate bounded first-order
values directly. Datom pull results, transaction maps, keywords, sets and
numbers stay native. No JSON serialization or field-name projection occurs.
The existing logic proof, application ceiling, resource membership, fresh roles,
code leases and provider Env still govern every invocation.

#+begin_src clojure
;; Host wiring supplies existing Datom readers and transaction ports to the
;; checked namespace. Consumers retain ordinary imported function calls.
(messages/change! "work" {:message/id "m1" :message/body "Hello"
                          :message/priority 0.75M :message/tag #{:urgent :work}})
(messages/services-in "work") ; native Datom pull data
#+end_src

Arguments and effect input use a 64 KiB first-order logical byte budget; reader
values and results use 1 MiB. Existing default node/depth limits also apply.
Validation never forces lazy values or invokes callbacks. Opaque arguments
refuse before effects. A host effect still owns transaction/schema validation;
this interface does not infer application contracts or undo committed work.

The HTTP JSON adapter retains its separate JSON shape and serialized-byte
bounds. It explicitly validates responses before emitting them; a native value
that cannot be represented by that protocol refuses at that boundary. Native
Unix RPC uses the separately bounded =data.first-order= codec instead.

[[file:../research/field-station/integration/evidence/auth-native-data.json][16 native integration assertions pass]] against the exact committed SDK.
The host fixture allocates transaction identity and converts its application
tag set into Datom's cardinality-many transaction vector. It verifies that the
authorization interface delivered the original map/set/decimal unchanged.
This does not qualify a production account directory or persistent service.

* Parameterized native reads

=auth.resource/query= is a new read-port intrinsic under SDK qualification.
It admits one bounded native data argument under the existing =:read= budget:

#+begin_src clojure
(ns ^{:auth {:version 1
             :exports {thread-state {:roles #{:member} :resource {:arg 0}
                                      :effects {:read #{:thread-state}}}}
             :grants {"station-cli" #{thread-state}}}}
  messages (:require [auth.resource :as resource]))
(defn thread-state [station thread]
  (resource/query :thread-state {:thread/id thread}))
#+end_src

The host enrolls =:queries {:thread-state (fn [principal resource query] ...)}=
alongside existing readers/effects. The same verified principal, fresh role and
resource checks precede it. Query input uses the 64 KiB logical data budget;
output uses 1 MiB. Opaque and oversized values refuse. There is no fallback
from a missing query handler to a reader or a general database connection.

The host validates the query's application schema and row visibility. This is
an enrolled application read, not permission to submit arbitrary Datalog to
the host database. Existing =resource/read= and its two-argument host reader
callbacks retain their behavior. Query admission is modeled as an unconstrained
read-port result by the existing logic analysis; no supplied proof gains authority.
