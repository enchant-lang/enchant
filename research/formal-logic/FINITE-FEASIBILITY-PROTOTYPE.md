# Feasible premises and conditional entailment are separate checks

The isolated source in `prototypes/finite-feasibility` is pending, has not run
and adds no capability to the SDK being qualified. The current SDK's finite
certificate result deliberately leaves assumption feasibility unestablished.

This next experiment reuses that checker. It derives a background SAT request
after bounded fresh original admission, by patching only mode, claim and
counterexample in the original public graph.
It verifies that the complete assertion graph stays byte-identical, including
generated domain/within/input-success conditions. Source metadata, observations,
labels and semantic scope stay in the subject. It uses the graph-native request
entry instead of a query materializer, so unfamiliar metadata and shared argument
trees need not be expanded or turned into application atoms.

The independent finite strategy can return a checked contradiction or find a
satisfying point. The latter is rechecked through the ordinary point interface
on that exact background question. A conditional theorem alone is neither of
these results. A refusal or unavailable replay establishes no feasibility fact.
The fixed reservation is 100,000 units for original admission, 3,300,000 for
the finite strategy, and 200,000 for fresh witness admission plus point work.
The total is 3,600,000 units. This is separate from the original request's
execution allowance and is no physical CPU/allocation theorem.

The planned gate must cover feasible and inconsistent Boolean/word premises,
changed assumptions, empty backgrounds, exact reservation limits, unsupported
sorts/quantifiers, solver-denied execution and large shared unfamiliar metadata.
It must also show that an infeasible premise can accompany a checked conditional
theorem without being presented as a useful unconditional program guarantee.

Before this joins the common interface, define how an explicit vacuity policy
uses the two results, compose their checking accounts, and preserve the exact
derivation and trust assumptions when saving/reopening. Neither result establishes
Source correspondence, compiler authority or language-wide totality.
