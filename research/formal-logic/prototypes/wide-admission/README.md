# Separate typing from the checking tools available for a theory

This is a project prototype, not an installed SDK profile. Its actual language
checks and corpus qualification are pending. Run only after the current dossier
writer/check/browser work has released the single substantive-check slot.

`formal.wide-admission/admit` accepts an original question graph and a closed
reader work allowance. It repeats raw capacity screening and SDK typing on every
call. Its derived inventory is diagnostic data; no consumer accepts that data
as a token that skips re-admission of the original graph.

A successful result reports these independent facts:

| Field | Meaning |
| --- | --- |
| `:status :admitted` | The original typed term inventory passed this bounded front end. |
| `:admitted-operators` | Operations actually present in the fresh inventory. |
| `:point-checking :not-installed` | This prototype adds no interpreter for those operations. |
| `:proof-strategies []` | It installs no certificate checker or semantic embedding. |
| `:native-execution :not-run` | Typing neither opens nor calls a native backend. |
| `:backend-support :not-observed` | Acceptance says nothing about Z3/OxiZ capabilities. |
| `:admission-authority :none` | The inventory is not a reusable execution capability. |

The front end bounds raw nodes, edges and bytes; integer carriers; scalar byte
lengths; term-shaped maps and arities; expanded selected descriptor sizes and
depths; total binder declarations; and aggregate selected descriptor occurrences.
It reserves rational literal normalization and a fixed constructor/scope budget
before entering generic SDK typing. The work convention is an abstract policy,
not a proved correspondence to BEAM time, instructions or heap allocation.
Oversized raw data and term-shaped metadata can be refused conservatively even
when that data would be ignored by the operational question inventory. They do
not become new premises, executable terms or proof authority.

The planned qualification covers all 187 retained questions using the same
immutable obligation SDK, with no native calls, plus explicit low-work,
shared-descriptor, large-literal, escaped-binder and unfamiliar-provenance cases.
It must retain failure evidence if the proposed limits or implementation are
wrong. A graph accepted here may still receive `unknown` or `unsupported` from
either native adapter.

The next integration step belongs to the existing common prepare/propose/recheck/
execute/compare interface and actual native owner. It needs a coordinated policy
split, unchanged retained-assumption custody, native reply projection, and
versioned candidate-only storage. It must not route around owner accounting or
reuse a narrow proof merely by renaming its semantic profile. An installed wide
profile can initially retain native claims while returning independent point
checking as unavailable. Actual per-theory replay and proof rules can then grow
behind their own named semantics and resource policies.
