* A good place to start again
#+begin_lede
We started by asking whether OxiZ could make formal logic feel more native to
Beam Lisp. The useful answer became bigger than a solver swap: make the
question, its assumptions, proposed answers and checking rules ordinary,
portable language terms. Then let either engine participate in that conversation.

There is now a substantial implementation behind that idea. The next team
should build on it in small, independently reviewable pieces. This file is the
map; the linked evidence is the record of what actually passed.
#+end_lede

#+begin_stats

94 | executed dossier cells | The last qualified presentation rechecks their unchanged sources and results.
8 | runtime files in the wider batch | Committed on main and packaged in one candidate SDK; final artifact qualification remains open.
#+end_stats

The ambition is a language where you can ask a precise question about a value,
function, transformation, loop or actor, keep the evidence, and inspect exactly
what makes it trustworthy. Some programs can live in a total, checked fragment;
other programs should expose their effects, partiality and remaining assumptions.
Changing semantic choices is allowed while BL is in preview. Please review them
properly instead of preserving an awkward choice just because it came first.

#+begin_honest :title "The checkpoint, without the victory lap"
This is not a verified compiler or a totally formal implementation of all BL.
We have implemented language interfaces, checkers and useful formal fragments,
plus separate mechanically checked mathematical models. Important bridges
between those models, BL implementations, Source compilation and BEAM execution
remain open. A native UNSAT report alone does not close them.
#+end_honest

* The architecture in plain language
The shared interface has four separate jobs. Keeping them separate is what
lets us grow theories without quietly growing the claims we make about them.

#+begin_rosetta
Question | What BL does | What that earns
May these terms enter? | Discover the operational roots, freshly type their graph and reserve bounded construction work. | Admission to a named policy; no solver or proof result.
What did an engine report? | Execute through an owned adapter and bind the answer to the complete request. | A recorded native report and candidate model fragments.
Does this proposed point work? | Run an installed independent interpreter against the original assertions. | A checked witness or counterexample in that interpreter's stated domain.
Does this argument prove it? | Check a closed proof strategy, then assess premises and acceptance policy separately. | A scoped checked conclusion, with its assumptions still attached.
#+end_rosetta

#+begin_sequence :title "One conversation, either backend"
lanes program · ordinary BL | request · portable data | adapter · Z3 or OxiZ | reader · independent checking
program -> request : Original terms, assumptions, observations and policy
request -> adapter : Fresh admission, owned execution and deadlines
adapter --> request : Native report and original candidate fragments
request => reader : Save the complete request and candidates as graph data
reader --> program : Recheck now; explain what is established and what remains a claim
note request, reader : No stored success flag, callable or expired execution lease becomes portable proof authority.
#+end_sequence

The public carriers are closed graph data. Shared term arguments remain
references rather than expanding into trees. Ignored provenance stays opaque;
a term-shaped map in metadata does not become executable logical syntax.
Execution capabilities stay local to their owner. A saved question carries the
complete retained assumptions, even if a client-side mirror is cleared.

* What is already implemented
** More than a backend experiment
The earlier work established typed terms, partial Int/Bool Core outcomes,
contracts, checked transformations, ranked loops, protocol invariants and
recorded traces. Source adapters preserve selected-unit and lexical environment
identities, expose declared intrinsics, and compare concrete original-unit
outcomes. Generator, response-contract and migration experiments use the same
questions rather than hiding a separate logic in each feature.

There are separate Lean models for core outcomes, refutation checking,
original-term entailment, witnesses, translations, loops, traces and graph
structure. Their theorem statements and axiom audits have explicit scopes.
The [[file:metatheory/README.md][model guide]] explains the implementation bridges
they do not establish. Start there before adding another theorem that restates
an assumption instead of closing one of those bridges.

** What we learned about nativeness
The language owns the question and its meaning; the adapter owns native
construction and execution. Both Z3 and OxiZ can sit behind a term interface.
OxiZ does not by itself make BL's integers, strings, actors or compiler formal.
The interesting comparison is what each adapter can construct, decide and
return through the same language contract, and how much BL can check afterwards.

The native smoke run shows this concretely: generic sequence empty/unit length
is UNSAT with Z3 and unsupported with the pinned OxiZ route. Structural equality
of the two signed zeros is SAT on both. We preserve those differences rather
than inventing an empty sequence or confusing FP structural equality with
numeric equality. See [[file:evidence/wide-owner-prototype/native-smoke/observations.json][the actual reports]].

* Decisions that deserve another careful look
These are semantic questions, not permission barriers. The next team may change
the preview language deliberately, with named profiles and explicit migration.

#+begin_principles
Values and representations | Exact numeric value equality and representation equality answer different questions. Collection key behavior must be reviewed alongside Decimal, Int, Float and cross-runtime behavior.
One word can hide several domains | BL scalar UTF-8 text, SMT codepoints, bytes and graphemes are not interchangeable. Native String quantification needs an actual domain connection, not descriptive metadata.
Failure is an outcome | Preserve which operand or branch fails and which error it raises. A solver's total arithmetic operator is not automatically BL's partial runtime operation.
A theorem can have unusable premises | Conditional entailment, premise feasibility and allow/report/reject vacuity policy remain separate judgments.
Totality needs a decreasing argument | A fuel-limited evaluator stopping is not a proof that the original program terminates. Actor safety also says nothing by itself about fair delivery or eventual progress.
#+end_principles

* Parallel work, with one integration hand
The next lead should delegate. Give each worker one question, an owned prototype
namespace/directory, the shared contract, and a concrete completion condition.
Workers may investigate and implement in parallel; they must book the single
check slot rather than starting competing BL loops. Only the integration lead
edits canonical runtime files, selects SDKs or produces the next SDK batch.

The public contract between workers stays small: original subject graph and
profile; separate resource policy; closed candidate data; named checker
availability; separate logical, feasibility and consumer judgments; explicit
Source/runtime premises. No task may smuggle executable callbacks into saved
evidence or accept a producer's checked result as authority.
