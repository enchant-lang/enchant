# Bound text work before decoding or building a string

The isolated `prototypes/text-resources` module is prepared source only. It has
not run, is outside the SDK and adds no managed theory capability. The selected
retained-request SDK and ongoing word SDK qualification remain unchanged.

The next managed profile should reuse the same request carrier, complete subject,
closed policy dispatcher, owner, graph coordinate syntax and fresh point scope.
There is no second term language or special text solver handle. A named profile
must distinguish UTF-8 bytes, Unicode codepoints and grapheme positions.

The existing canonical evaluator's String theory uses Unicode codepoint
positions. Its value checker requires valid UTF-8 and an alphabet bounded by
196607; this is not arbitrary BL binary data or the full set of Unicode scalars.
The native workers already import actual scalar values: Z3 uses its u32-string
API and OxiZ uses native string terms. Existing native cases distinguish bytes,
combining characters, NUL, escape-looking data and the alphabet boundary. Those
are current implementation sources; this pending planner adds no native support.

The planner accepts UTF-8 byte upper bounds and index integers. It constructs
no text, parses no UTF-8 and asserts no alphabet validity. Actual byte size must
be derived freshly from the original literal or coordinate before calling it.
After reserving the value plan, the point may invoke its existing validity and
alphabet checks. An unavailable coordinate, an empty string and an invalid
binary remain distinct observations.

Prospective envelopes separate input bytes, result bytes, temporary scalar slots,
integer-result bits and work. Byte count bounds codepoint count without first
allocating a character list. The existing `seq-index` implementation repeatedly
uses drop/take and vector reconstruction; the convention therefore charges a
quadratic term in the largest input as well as the text/needle product. Prefix
currently calls that search too. A future faster primitive requires its own
reviewed envelope; this planner does not assume one.

Concatenation reserves both inputs' maximum bytes before allocation. Replacement
reserves input plus replacement bytes, covering insertion for an empty needle.
At and substring use conservative UTF-8 output bounds and total empty results
for their stated invalid positions/lengths. Index positions use codepoint units;
result integers get a separate size forecast. Existing input integers are
charged by their encoded size before forecast arithmetic. Operand count and
oversized input bounds refuse before result forecasting.

Plans are ordinary data. Their input reference binds only the supplied size,
index and policy parameters. It neither binds actual text bytes nor authenticates
producer measurements, performs reservation, creates an admitted term forest or
establishes a checked value. The actual point must derive and charge its own plan.
The counts are a policy convention, not a physical allocation or CPU theorem.
Graph capacity, aggregate point accounts and process deadlines remain separate.

Prepared checks compare the envelopes with actual SDK primitives over ASCII,
multibyte scalars, a combining sequence, a supplementary-plane scalar and NUL.
They cover exact work limits, oversized outputs/inputs, large integer positions,
malformed policies and a calibrated private codepoint-conversion counter that
must stay zero during planning. These checks are not passing evidence until the
real capped runner completes.

After this groundwork is qualified, the canonical batch needs fresh literal
admission, syntax-only text coordinates, demanded value/operation charges, a
named combined checking profile, both actual owners and solver-denied fresh
saved-record readers. Mapping BL grapheme operations or Source program outcomes
to scalar-text terms remains a separate semantic and implementation obligation.
