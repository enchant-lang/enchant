Checkpoint 40 — typed migration preview

A closed migration is an explicit model of admission and transformation. It is
not mailbox delivery authority. Ordered Bool/Int parameters select exact input
identities. One role is the old message. A transform is authored terms or one
quoted BL function translated through the real compiler ANF. Admission before
and after may differ, because message contracts change. Normal completion of
the transform and of the new admission predicate are proof obligations.

The interface reconstructs three questions: admitted inputs, conditional
preservation/equivalence, and counterexample existence. It distinguishes a
checked conditional certificate from a feasible admission and from a checked
counterexample. `verified` is true only with a fresh certificate AND checked
admission evidence, false only with a checked counterexample, nil otherwise.
Native UNSAT alone is uncertified. Inconsistency is vacuous. No result claims
mailbox migration, correspondence of an arbitrary :fn, or compiler preservation.

The new default two-argument reload.migrate/verify-migration accepts this closed
definition (or a migration spec carrying :formal-model). The old three-argument
script path remains explicitly legacy; existing source invariant discovery
must not silently become an authored typed invariant. Qualification retains its
legacy regressions, with owned native sessions closed in test cleanup.
