# Integrate words through the existing request, owner and evidence machinery

The selected retained-request SDK has completed its qualification. The next
runtime batch can extend its theory profile using the standalone word prototype
(3,526 assertions) and the separate word-envelope model (six theorems). Neither
artifact by itself adds managed word solving.

## Keep representation and semantic policy separate

Preserve the portable request carrier, exact complete-subject reference,
retained composition and two execution lifetimes. Add a named combined
Bool/Int/Real/word checking policy; keep the existing numeric policy and its
saved readers unchanged. Backend choice remains adapter data. No new term tree,
owner identity, cached checked view or solver handle belongs in that carrier.

The fresh answer v2 and retained answer v3 encode different provenance contracts.
Adding a theory should not automatically create a third ownership contract.
Their existing bound request policy can identify the new semantic profile; an
older reader must refuse that unknown policy. The owner primitive currently
emits a numeric-named reply v2. Introduce a generic managed reply envelope for
new profiles and retain the old reply under its exact numeric contract.

Use one closed SDK dispatcher for settings, question admission, coordinate
syntax and replay. It can import the existing evaluator, graph-question reader
and coordinate modules without importing a backend or request runtime. Both
the owner turn and fresh saved-answer reader call this dispatcher. A capability
descriptor reports admission, native observations, coordinates, replay, resource
policy and proof support as separate axes. It must not turn a constructor list
into a completeness claim.

## Reserve before constructors and before demanded primitives

Extend graph-terms admission to inspect every actual term sort and declaration
before invoking constructors. Include unused quantifier binders; UF domain
arguments and return sorts must agree with their declarations. Retained origins
and unrelated observation metadata remain opaque original graph data.

The whole admission reserves word-literal checking and normalization before any
constructor runs, including inactive syntax. Width checks precede powers and
masks. The existing constructor width ceiling remains a separate fixed boundary;
changing a resource override cannot enlarge that language grammar.

During point replay, use the existing private primitive dispatcher. Add the
word planner before each demanded operation and reserve aggregate request work
before executing it. Share no caller-provided prepared forest, checked-child
flag, charged counter or normalization result. Keep mathematical Boolean demand
and selected branches; do not infer BL raisedness or evaluation order from them.

The word planner distinguishes result width, intermediate width and a named
work charge. Multiplication and unsaturated left shift can need twice the input
width; wrapping constructs a power one bit wider than the output. This policy
is not an implementation-cost theorem. The Lean model establishes separate
natural-number arithmetic bounds, without proving bit-mask or signed semantics.

## Parse coordinate syntax, then check values under the actual point account

Extend the closed coordinate grammar with the reserved word wrapper while
leaving unknown application names as graph cursors. Do not treat a decoder's
returned `:checked` label or charge summary as authority. The actual point owns
its resource account and freshly checks the raw coordinate against the declared
variable sort before existing SDK value semantics runs.

The standalone coordinate prototype checks and charges eagerly in canonical
graph order. Its profile remains explicit. For the managed integration, prefer
syntax-only graph reading followed by demand-owned value checking, so native
and supplied points share one account and do not trust or repeat a decoder's
normalization. Invalid or unused extra coordinates must follow a stated policy;
the existing numeric carrier validates the name-map shape and interprets only
the coordinates required by its subject.

Reserve for the actual already-present integer size, not only its claimed word
width. A tiny width with a huge malformed bit value cannot bypass the account.
Whole graph parsing/capacity is an earlier separate limit. Missing and unavailable
values stay incomplete; invalid values stay invalid. Unchecked native SAT or
UNSAT cannot acquire proof authority through the new decoder.

## Batch the production change and qualify one immutable SDK

The likely source pieces are the shared profile dispatcher, word resource
planner, coordinate grammar, graph admission, evaluator reservation, managed
reply binder and request point/no-point readers. The separate indexed-ledger
lookup proposal can join the same reviewed source batch if its payload tests
are ready; it changes storage access, not logical authority.

Before selecting that SDK, exercise every current word primitive, exact and
malformed coordinates, arithmetic/sign/shift boundaries, inactive declarations,
aggregate admission and point budgets, both native imports/outcomes and fresh
solver-denied record readers. Preserve all earlier numeric and retained answer
contracts and compare the existing 187 native questions without changing native
deadlines. Record any intentional vocabulary migration separately. Keep the
compiler floor and worker/library components pinned where unchanged, and use
one SDK for the whole batch.

After qualification, add actual managed word examples to the live Org dossier,
run its real writer and unchanged check, and inspect the phone/desktop browser
frames. Text/sequences, IEEE data, finite collections, symbolic structures and
quantified/temporal profiles follow this same architecture with their own
semantic and resource obligations. The full formal/total language goal remains
active.
