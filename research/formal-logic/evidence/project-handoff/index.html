A good place to start again

We started by asking whether OxiZ could make formal logic feel more native to Beam Lisp. The useful answer became bigger than a solver swap: make the question, its assumptions, proposed answers and checking rules ordinary, portable language terms. Then let either engine participate in that conversation.

There is now a substantial implementation behind that idea. The next team should build on it in small, independently reviewable pieces. This file is the map; the linked evidence is the record of what actually passed.

187existing question vocabulariesThe wider pure admission route covers the existing corpus; this is not 187 complete theories.
2native adaptersZ3 and OxiZ receive the same mathematical subjects.
94executed dossier cellsThe last qualified presentation rechecks their unchanged sources and results.
8runtime files in the wider batchCommitted on main and packaged in one candidate SDK; final artifact qualification remains open.

The ambition is a language where you can ask a precise question about a value, function, transformation, loop or actor, keep the evidence, and inspect exactly what makes it trustworthy. Some programs can live in a total, checked fragment; other programs should expose their effects, partiality and remaining assumptions. Changing semantic choices is allowed while BL is in preview. Please review them properly instead of preserving an awkward choice just because it came first.

The checkpoint, without the victory lap

This is not a verified compiler or a totally formal implementation of all BL. We have implemented language interfaces, checkers and useful formal fragments, plus separate mechanically checked mathematical models. Important bridges between those models, BL implementations, Source compilation and BEAM execution remain open. A native UNSAT report alone does not close them.

Read this file first, then the relevant task brief. Use the explanatory dossier for the longer story and the implementation index for earlier checkpoints. The existing live dossier stays available on its last qualified selected SDK.

The shared interface has four separate jobs. Keeping them separate is what lets us grow theories without quietly growing the claims we make about them.

As a diagram

The common facade is already in code:

This is an illustrative excerpt, not an executed cell. The wider policy is in main's source and the new candidate SDK. The project's selected SDK is still the preceding qualified artifact. See the exact facade batch.

The public carriers are closed graph data. Shared term arguments remain references rather than expanding into trees. Ignored provenance stays opaque; a term-shaped map in metadata does not become executable logical syntax. Execution capabilities stay local to their owner. A saved question carries the complete retained assumptions, even if a client-side mirror is cleared.

What is already implemented

More than a backend experiment

The earlier work established typed terms, partial Int/Bool Core outcomes, contracts, checked transformations, ranked loops, protocol invariants and recorded traces. Source adapters preserve selected-unit and lexical environment identities, expose declared intrinsics, and compare concrete original-unit outcomes. Generator, response-contract and migration experiments use the same questions rather than hiding a separate logic in each feature.

There are separate Lean models for core outcomes, refutation checking, original-term entailment, witnesses, translations, loops, traces and graph structure. Their theorem statements and axiom audits have explicit scopes. The model guide explains the implementation bridges they do not establish. Start there before adding another theorem that restates an assumption instead of closing one of those bridges.

For the wider policy, independent point replay and proof strategies are explicitly not installed. SAT therefore remains a candidate, and UNSAT a solver claim. This is intentional, not a missing status flag to flip. The narrower policies retain their existing independently checked fragments.

What we learned about nativeness

The language owns the question and its meaning; the adapter owns native construction and execution. Both Z3 and OxiZ can sit behind a term interface. OxiZ does not by itself make BL's integers, strings, actors or compiler formal. The interesting comparison is what each adapter can construct, decide and return through the same language contract, and how much BL can check afterwards.

The native smoke run shows this concretely: generic sequence empty/unit length is UNSAT with Z3 and unsupported with the pinned OxiZ route. Structural equality of the two signed zeros is SAT on both. We preserve those differences rather than inventing an empty sequence or confusing FP structural equality with numeric equality. See the actual reports.

Decisions that deserve another careful look

These are semantic questions, not permission barriers. The next team may change the preview language deliberately, with named profiles and explicit migration.

  1. Values and representationsExact numeric value equality and representation equality answer different questions. Collection key behavior must be reviewed alongside Decimal, Int, Float and cross-runtime behavior.
  2. One word can hide several domainsBL scalar UTF-8 text, SMT codepoints, bytes and graphemes are not interchangeable. Native String quantification needs an actual domain connection, not descriptive metadata.
  3. Failure is an outcomePreserve which operand or branch fails and which error it raises. A solver's total arithmetic operator is not automatically BL's partial runtime operation.
  4. A theorem can have unusable premisesConditional entailment, premise feasibility and allow/report/reject vacuity policy remain separate judgments.
  5. Totality needs a decreasing argumentA fuel-limited evaluator stopping is not a proof that the original program terminates. Actor safety also says nothing by itself about fair delivery or eventual progress.

The relevant starting points are the semantic review, key semantics, scalar text, native string carriers, vacuity and the qualified numeric repairs.

Workers may investigate and implement in parallel; they must book the single check slot rather than starting competing BL loops.
