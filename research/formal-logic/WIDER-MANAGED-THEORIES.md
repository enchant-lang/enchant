# Extend the theory profile, keep the portable question

The retained-request batch establishes the ownership and evidence boundary.
Its managed execution profile remains bounded Boolean/integer/rational-real
checking. The SDK already has general graph evaluation and shared private
primitive dispatch, exercised against the earlier tree evaluator across the
187-question corpus. That general profile accepts no derived-value resource
overrides. It must not be relabeled as the bounded managed interface.

The next change should extend this machinery through explicit profiles, rather
than build another term, context or saved-answer representation.

## Shared contract

Keep the portable request carrier, exact complete-subject reference and retained
composition unchanged. Execution policy names the theory/replay/resource
profile. The owner and fresh reader dispatch to the same SDK implementation.
Existing numeric profiles and their readers retain their exact contracts.

Separate the managed reply envelope version from its arithmetic profile. The
current reply is explicitly named numeric v2. A wider reply needs a generic
named envelope, with original/effective graph binding and native status claims
preserved. Constructor admission, model-coordinate admission and point replay
remain separate phases. A missing decoder cannot silently become a fabricated
coordinate or a solver-independent proof.

Each theory descriptor should report these axes separately:

| Axis | Evidence or contract |
|---|---|
| Terms | Typed constructors and original graph admission |
| Native import | Backend-reported operations and qualified import cases |
| Native outcomes | Actual SAT/UNSAT/unknown/unsupported observations |
| Coordinates | Versioned canonical values and explicit unavailable forms |
| Point replay | Independently executed semantics and covered operations |
| Resources | Admission limits and prospective derived-value forecasts |
| Source connection | Reviewed or checked connection to actual BL outcomes |
| Certificates | Named proof format, checker and assumption ledger |

An operation appearing in a backend's constructor table establishes neither
decision completeness nor support in the managed point evaluator.

## Implementation order

| Profile | Native language features | Required semantic review |
|---|---|---|
| Fixed-width words | Modular arithmetic, signed views, masks, packed records and binary fields | Width, signedness, overflow, division edge cases and exact bits |
| Text and finite sequences | Text constraints, parsers, structural length and sequence operations | Bytes, Unicode scalar positions and graphemes; missing versus empty values |
| IEEE data | Bit-preserving floating-point constraints and rounding contracts | Mathematical FP values, representative encodings and actual finite BL Float outcomes |
| Finite collections | Membership, cardinality, maps with explicit presence and finite array observations | Key equality, missing versus present-nil, finite scope and extensional equality |
| Symbolic structures | Datatypes, recursive data and uninterpreted functions | Well-formed declarations, inhabitation, partial models and observation coverage |
| Quantified and temporal properties | Invariants, bounded traces and declared unbounded obligations | Quantifier domains, fairness, vacuity and the exact proof/counterexample basis |

The first bounded word profile can reuse the SDK's existing general primitive
semantics. It needs prospective work/value-size plans and a canonical coordinate
format before becoming a managed request capability. Admission must check
unused sorts, signatures and binders too, as the numeric profile already does.

## Bound derived values before allocating them

A short shared term graph can describe an enormous derived value. String
doubling, growing sequences, large set supports and arithmetic shifts require
their own forecasts. Original graph-size limits do not bound those results.

Reserve work before primitive calls and literal/coordinate normalization.
Check widths before constructing powers of two. Charge input, intermediate and
result sizes under the same named policy in native-result and supplied-point
routes. Preserve Boolean demand and selected-branch behavior, while validating
the complete declared syntax. Budget refusal remains incomplete evaluation.
Native solver and hard worker deadlines remain separate from BL replay costs.

## Keep mathematical terms and program outcomes connected explicitly

General mathematical term evaluation does not by itself describe BL evaluation
order, raisedness, effects or runtime kinds. Source lowering must retain those
outcomes explicitly. A returned Int and a numerically equal Float can still be
distinguished by a program. A finite model universe needs its own domain facts.

Qualify every new profile with actual native import/status cases on both
backends, exact supplied points, malformed and unavailable coordinates, resource
boundaries, fresh solver-denied saved-record readers and Source observations
where a program connection is claimed. Kernel certificates keep their own
proof format and assumptions. The broader formal/total-language goal remains
active beyond each profile.
