** Keep every assumption with the question
A solver session remembers facts. Your next question may mention only some of them. Beam Lisp can now freeze the complete question before execution: the caller's terms, every retained assumption, the checking policy and the requested backend settings.

Suppose the session remembers =x = 7= and the caller asks for =x ≤ 9=. The point =x = 8= fits the caller's line but breaks the remembered fact. The [[#cell-story-retained-request][executed example]] rejects it against the complete question. The same frozen question can go through the existing owner, a fresh Z3 or OxiZ owner, a supplied point handler, or a saved-record reader.

#+begin_rosetta :title "What travels, and what stays local"
Piece | What it contains | What you can rely on
Portable request | Complete question, policy and adapter settings | Every retained assumption is part of the subject.
Recorded composition | Caller graph, retained graph, declared generation and revision | The complete bytes can be rebuilt and checked.
Local execution callback | Actual owner and captured guard | Same-process, single-use execution during its body.
Saved native answer | A status claim and any returned coordinates | Coordinates get fresh replay; native history remains recorded data.
#+end_rosetta

#+begin_graph :title "Keep meaning portable, execution local"
node caller | Caller question | Original terms | 0,0 | you
node retained | Retained facts | Explicit assumptions | 0,1 | station
node complete | Complete question | Portable graph data | 1,0 | door
node choice | Execution choice | Owner or handler | 2,0 | builder
node replay | Fresh replay | Check the full point | 3,0 | you
edge caller -> complete | freeze | solid
edge retained -> complete | include | solid
edge complete -> choice | ask | solid
edge choice -> replay | inspect | solid
#+end_graph

#+begin_sequence :title "A remembered fact never becomes a hidden premise"
lanes caller · your program | owner · live context | handler · request effect | reader · fresh checking
caller -> owner : Read actual facts and adapter settings atomically.
owner --> caller : Return a snapshot for the complete portable question.
caller -> handler : Offer that question and a short-lived native fallback.
handler -> owner : Optionally invoke the fallback under its captured guard.
owner --> handler : Return a status claim and any candidate coordinates.
handler -> reader : Recheck the returned point against every assumption.
note caller, reader : A saved record keeps the complete subject. A local callback does not travel with it.
#+end_sequence

There are two lifetimes. The outer execution callback ends with its request body. A handler's fallback ends as soon as that individual execution returns, even while the outer body is still open. Changing the live context or requested settings cannot silently change the frozen subject.

The [[file:evidence/retained-request/records-qualification.json][fresh-record receipt]] reopens the actual saved packets and durable ledger rows in two separate SDK-only processes, with formal solver exchanges and oracle methods denied. Wrong points stay invalid after re-encoding. Edited history stays recorded history. A proof requires its own checked object.

The current managed request profile admits Boolean, integer and exact rational real graphs. Wider theory profiles and their resource rules remain active work. This checkpoint strengthens term passing, state ownership and replay for both backends; it does not finish the formal-language goal.
