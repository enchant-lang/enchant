# Finish the common interface across the whole term vocabulary

The selected evidence SDK is qualified. Its portable request still has three
closed checking profiles: numeric, numeric/word, and numeric/word/scalar-text.
They couple fresh original-graph admission to the corresponding pure point
interpreter. The wider 187-question corpus uses the older graph/native route.
Arrays, generic sequences, datatypes, uninterpreted functions, quantifiers and
SMT floating-point therefore do not yet have equal access through the newer
request/evidence envelope. Passing that corpus does not close this interface gap.

The [wide-owner source prototype](../prototypes/wide-owner/README.md) now implements
this separation beside the immutable SDK. Its
[pure qualification](../evidence/wide-owner-prototype/pure/qualification.json)
passed 424 assertions over all 187 existing question vocabularies, with six
measured zero-exchange windows. Actual native owners, narrow-policy regressions,
fresh candidate readers and immutable SDK installation have distinct gates.

Keep the current original-graph request, closed data carriers, expiring local
execution leases and exact original/retained assumption binding. Separate these
four responsibilities when adding the wider route:

| Responsibility | What it establishes | What it must not imply |
| --- | --- | --- |
| Typed graph admission | Well-scoped terms and bounded literal/sort construction | A point interpreter or solver supports every operator |
| Native execution | The requested adapter reports status/model data for these original terms | UNSAT is an independently checked theorem |
| Point checking | Supplied coordinates satisfy every original assertion/counterexample root under an installed semantics | Unsupported coordinates or operations are false |
| Certificate checking | A closed installed proof strategy checks the exact statement | A producer verdict or backend proof pointer is authority |

An initial wide native profile may admit the full supported typed graph and
return native claims while explicitly leaving point checking unavailable.
This is more useful than refusing a theory before the native adapter sees it,
and more honest than treating unsupported replay as a checked witness. Keep
partial model data as original graph data; do not decode application keywords
or invent host values for opaque arrays, functions, regexes or floating values.
Native UNKNOWN and unsupported remain first-class outcomes.

Admission still needs prospective limits before constructors: integer/rational
normalization, bit-vector and FP widths, sort nesting, quantifier environments,
term nodes, retained graph imports and raw scalar bytes. A wide profile must
not bypass the existing bounded-literal discipline. Backend deadlines and owner
custody stay separate from these language checking budgets.

Initially retain the current proof semantic profiles. Reusing a narrow proof
under a broader profile needs a named checked semantic embedding, not a casual
profile substitution. Similarly, adding point replay to the wide route needs
a precise subset relation and an all-original-roots success criterion. A
profile describes semantics and verified checking capabilities; it is not an
engine marketing label. A larger caller allowance cannot enlarge its theory.

The same public prepare/propose/recheck/execute/compare operations should serve
all profiles. Descriptions should expose admitted operators, independently
replayed operators, installed proof strategies and observed backend support as
separate fields. Backend comparison must keep the exact original question and
semantic profile, changing only the requested adapter settings.

Migrate model consumers through fresh closed term obligations, using the existing
model-plan framework rather than shadowing it. Source expansion/admission is a
separate effectful front-end stage. Portable proof readers must not execute a
stored Source initializer or macro. Keep reviewed Source/core interpretation,
term normalization, proof soundness and compiler preservation as distinct links.
The old native-only `:proved`/`oracle/proven?` vocabulary and raw SMT script
consumers still require deliberate migration before declaring the formal logic
interface uniformly term-based.

## A concrete String-domain extension after the interface split

The immutable OxiZ 0.3.4 sources actually provide regex builders in
`src/ast/manager/builder.rs`: singleton, concatenation, union, intersection,
star, complement, range and membership. Their reserved RegLan representation
is an interned built-in sort plus canonical Apply operators. The current worker
does not expose those operations. This is source availability, not a tested
solver capability or a new BL interface.

A term-native scalar domain can be expressed by membership in the star of the
union of codepoint ranges 0..D7FF and E000..2FFFF. Both endpoints can themselves
be represented as valid UTF-8; no surrogate literal is needed. This is a proposed
predicate construction to test on both native adapters. Quantified variables
need that predicate in their actual guards/assumptions, not only in metadata.

An independent regex point checker needs its own bounded construction and
matching policy. A shared regex DAG is not permission to reuse automaton entry/
exit states blindly: concatenating the same fragment twice must still require
two matches. Forecast expanded positions or use an independently justified
symbolic algorithm, refusing before excessive state construction. Complement
and intersection may need a stricter profile. Do not turn a native membership
answer into a checked String proof without that separate argument.

A worker change also requires historical reader review: old recorded worker
labels belong to the pinned producer, not the current reader's worker. Fresh
term/point checking can remain valid across worker versions when its semantic
profile is unchanged. It must not authenticate the recorded execution merely
because artifact labels match.
