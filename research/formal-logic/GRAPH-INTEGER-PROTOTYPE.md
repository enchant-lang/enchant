# A graph-native boundary for unbounded integer proofs

The isolated `prototypes/graph-integer` source passed all 54 assertions on the
qualified and selected scalar SDK. All seven named test bodies and both actual
checked observations were captured during execution; the source-bound report is
`evidence/graph-integer-prototype/qualification.json`. It changes no SDK code
and is not yet installed in the common evidence bundle.

The current independent integer checker accepts materialized term queries.
This prototype explores an original-graph entry without expanding shared terms
or decoding unfamiliar metadata. It freshly admits the complete original
request through the SDK, derives affine integer rows once per typed node and
builds a shared Boolean formula DAG. The assumption ledger retains labels and
original source-node references. Its statement binds the entire subject and
named numeric semantics while excluding backend/deadline choices.

A candidate supplies only a finite proof DAG: Boolean contradiction leaves,
Boolean atom splits, and positive weighted sums of derived integer inequalities.
It cannot supply normalized atoms, arithmetic premises, trusted inventories or
checked flags. The checker derives every row again, checks both split branches
and revisits shared proof nodes under each assignment context. Integer strict
inequalities use the discrete integer complement rule. No native solver or
oracle is required. Unlike finite word exhaustion, this rule system does not
enumerate variable values: a valid linear refutation excludes every mathematical
integer assignment. The coefficient/representation limits constrain the checker
input and its work, not the logical range of those integer variables.

The initial profile supports Boolean connectives and affine integer expressions
with multiplication by constants. It deliberately excludes integer conditionals,
nonlinear products, division/modulus, Real and wider theories. It does not
replace the existing piecewise/ground integer kernel or claim all its features.
There is no proof search implementation in this prototype.

Normalization and proof traversal have finite node, atom, variable, depth and
context limits. Integer addition, subtraction, negation and multiplication use
the installed prospective primitive planner before execution. Formula and
argument visits also reserve logical work. Coefficients remain bounded to 128
bits regardless of a larger caller allowance. These policy units are not a
physical allocation/time theorem. Insufficient admission work invokes no fresh
admission; an arithmetic reservation refusal does not establish a false theorem.

Seven actual tests cover nontrivial unbounded entailment, false conclusions,
backend-independent statement identity, shared proof leaves under opposite
assignments, positive arithmetic weights, integer strictness, SAT contradictions,
shared million-node expansions with unknown metadata, grammar/resource refusals,
closed certificate shapes and actual native/oracle invocation denial. The runner
required all seven named bodies, at least fifty assertions, the actual captured
results and an unchanged committed source pin. The actual run passed 54.

The qualified prototype still needs review, legacy integer correspondence,
independent cold packet checks, common strategy dispatch and durable storage
before runtime integration. Mechanical checker soundness, Source semantics and
compiler preservation remain separate obligations.

The first run passed 54 assertions but failed qualification because a top-level
artifact write ran before the test bodies. Its empty capture, actual exit and
source pin remain in `evidence/graph-integer-prototype/before-runtime-observation-capture`.
The successful retry moved capture inside actual test execution; it did not
change the checker implementation or reduce its assertions.
