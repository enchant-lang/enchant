The reusable implementation now lives in priv/lib/auth and
priv/lib/veritas/assurance.bl. bl.env reads the declarations and normal bl.cli
project startup activates them before compiling application code. Generated
import files and a research source directory are no longer required by the
native runtime.

#+begin_src clojure
(ns my.app (:require [station.services :as station]))
(station/services-in "knowledger")
#+end_src

Application code uses the same interface for another Env or VM. It supplies a
project identity, not a folder, bearer, role list or RPC request.

* Namespace policy and environment placement

The provider owns its explicit exports, application grants, resource selection,
role requirements and effect budgets using existing namespace metadata:

#+begin_src clojure
(ns ^{:auth {:version 1
             :exports {services-in {:roles #{:viewer :operator}
                                    :resource {:arg 0}
                                    :effects {:read #{:catalog}}}}
             :grants {"team-machine-next" #{services-in}}}}
 workstation.services
 (:require [auth.resource :as resource]))
(defn services-in [project] (resource/read :catalog))
#+end_src

A consumer declares only its desired surface and deployment binding:

#+begin_src clojure
{:name "team-machine-next"
 :paths ["src"]
 :auth/imports {station.services {:from :station :namespace workstation.services
                                 :version 1 :only [services-in]}}
 :auth/realms {:station {:root "/path/to/workstation/services" :transport :local}}}
#+end_src

The provider's :auth/realm declares its source, world, host factory and private
operator policy. The native reader also accepts the earlier namespaced prefix
blocks before a normal trailing project map. It rejects malformed and duplicate
auth declarations. Unknown identities, missing grants, empty roles and unsupported
source never become ambient access.

Pure functions use :effects :pure. Read and mutation ports are explicit and
scoped to the authenticated subject and authorized resource. Membership comes
from the provider, not caller headers or arguments. A host resolver may map an
object argument to its owning resource. Workstation's initial surface remains
read-only: services-in and inspect.

* Identity and remote calls

auth.identity uses the runtime's registered callable context. Native tasks and
Env conveyance carry it and retain its executable dependencies automatically;
nested extents restore the previous context. Verified ingress remains trusted
host code. The example entry supplies a fixture identity, not a login shortcut.

Tailscale, Headscale with Tailscale ingress, the existing Workstation NetBird
gateway, and station identity headers normalize to the same subject/application/
kind model through auth.strategy. A header requires trusted connecting-socket
UID evidence or a host verifier. Tailscale-style ingress also rejects self/local
sources; the configured gateway must sanitize headers and reject tagged/shared
node human misattribution. Host configuration maps external subjects to station
accounts before the app's provider-neutral person mapping runs. The adapters
were contract tested; an actual mesh migration is separate operational work.

For another VM, publish auth.contract/publish!'s bounded public interface data.
Use :transport :remote with :interface, :world, :url and :issuer-public. The
consumer needs no implementation source. Namespace, version and exported arities
form a canonical interface fingerprint checked at both ends. Protocol version 2
and namespace contract versions are separate from SDK versions.

A remote realm may configure a private token file or a host :delegation broker.
The broker uses issuer-file, authority-file, application, world, namespace and an
export ceiling. It requires the current verified caller and current resource
membership, then issues one short-lived signed namespace/operation/resource right.
The app handles no bearer strings or issuer keys. The receiver independently
checks signature, audience, expiry, revocation, application grant and fresh roles.
Removing explicit revocation policy denies requests. A person's token cannot
substitute another person.

Remote credentials require TLS by default. The isolated test explicitly enables
:allow-loopback-http? for exact 127.0.0.1; this test transport does not defend
against a hostile local listener. RPC rejects browser Origin and uses bounded
connector.transport requests without redirects or automatic retries.

* Assurance and lifetime

auth.logic checks the actual source and transitive helper graph through existing
compiler ANF/footprint analysis. Explicit resource ports are modeled with unknown
finite results, so branches cannot disappear through constant stubs. Purity
annotations are checked assertions. Ambient I/O, opaque calls, top-level effects,
unsupported signatures and unsupported metadata refuse publication. The check is
bound to source, compiler generation and exact executable identities.

Veritas exhausts all 32 boolean combinations of the actual entry gate:
authentication, application, role, resource and current code. veritas.assurance
preserves modality; samples, unknown results and solver claims are not promoted
to proofs. No caller-supplied proof receipt is accepted as authority.

This covers an admitted source/ANF fragment and finite policy, not arbitrary
programs, termination, the whole compiler/runtime or filesystem semantics. Host
ports, verifiers, compiler/analyzer, operator policy and runtime guards remain
trusted components. PIDs, Env handles, callbacks and arbitrary executable values
never cross the finite-data boundary.

Warm local providers are realm services. Their scopes close on normal stop and
owner death. A later call can reacquire a crashed provider; an interrupted call
is never replayed. Relinking retires old function references. Repeated activation
reuses unchanged bindings; changed source/interface data is admitted again.
Embedded hosts close explicit imports with imports/close!. A remote failure can
still have an uncertain outcome. Real mutation ports must own durable idempotency
and recoverable receipts.

There is one authoritative provider per account and one owner per domain writer.
No consensus layer is needed for namespace lookup or inventory projection. The
VPS/fleet research places consensus and fencing at a future replicated writer.
Cached observations and interface advertisements confer no authority.

* Application integration and evidence

Team Machine Next consumes the namespace; Workstation owns its inventory and
resource-port adapters under services/src/workstation. Project roles bind stable
subjects to physical project roots. Successful refresh replaces saved observations;
failure retains the previous values, which expire locally after at most 15 seconds.
Only currently resolvable folders enter the inventory. No secondary scanner or
service registry is added.

The canonical checks are test/bl/auth/namespace*_test.bl. check_namespaces.py
runs independent VMs with distinct immutable SDKs, a source-free consumer
interface, temporary issuer material, live role/revocation changes and the host
credential broker. It stops its provider and removes its private temporary state.

Earlier source prototype results remain in evidence/qualification.json and
evidence/namespaces-qualification.json. The source prototype is retained at Git
ref refs/archive/service-world-source-prototype with a local recovery bundle.
They are historical results, not qualification of the native SDK. Native SDK,
example and application results are recorded in
[[file:evidence/native-namespaces-qualification.json][native-namespaces-qualification.json]]: 118 native assertions, 15 cross-VM
assertions and 176 application/editor assertions passed on the exact SDK now
pinned by both projects. The real read-only Station rehearsal returned 109
observations across five places, each checked against its physical project root.

Team Machine retains only the previous SDK's live.edit namespace tree and assets
as an immutable application dependency, because this checkout's SDK does not
contain that editor package. The binding and provenance live in the application's
vendor/editor/README.org. It does not add the old SDK's general library root.
Both immutable artifacts have retained GC roots. No production service was
restarted or public endpoint installed as part of this source integration.
