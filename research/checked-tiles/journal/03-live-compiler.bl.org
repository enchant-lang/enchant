* What should happen when I save?

#+begin_lede
A scene is playing. Its author changes how two layers blend. The editor should explain a bad rounding decision in terms of a pixel. A correct edit should become visible as soon as the ordinary executable satisfies the application's law. The renderer can adopt a faster implementation of that same revision when its own checks finish. The frame already on screen and the requests already in flight must keep their meaning throughout.
#+end_lede

My proposed unit of compilation is an ordinary resolved function together with the dependencies needed to explain its behavior to a caller. My proposed unit of activation is an immutable application revision. A revision can refer to several independently reusable functions and several legal ways to execute each one. Separating those lifetimes gives us a way to save compilation time, qualify stronger optimizations, and keep the app available during both.

#+begin_sequence :title "One save, two decisions about what may run"
lanes a · author | w · Source and compiler | p · independent checker | o · running owner | r · renderer
a -> w : save an implementation against its declared law
w -> p : selected definition, dependencies, typed claim and source locations
p --> o : evidence for this revision's ordinary executable under the declared trust policy
o -> r : select revision B for new work while outstanding work retains A
w -> p : candidate machine region, transformation premises and target evidence for B
p --> o : checked accelerator for B and its launch conditions
o -> r : choose a qualified variant when the next request satisfies its guards
note o, r : Publication checks the current request and revision again. A newer edit can supersede either check.
#+end_sequence

* Four findings that changed this design

1. *The old blend result answers a narrower question than I first thought.* The lowerer's example BL takes an =out= argument, builds a vector, and returns =n=. Its store emitter writes into argument zero and returns the length. The separate BEAM reference returns its accumulated pixels. Matching the JIT bytes against that reference is good arithmetic evidence. It leaves open the adapter's obligations about the original return value, whether a caller can see a write, and what happens on error. The production gate should capture the actual linked export and compare results, permitted errors and effects at its real calling boundary. Keep the old experiment as a control. [[file:../../lowerers_spike/lower2.bl][Kernel source and emitter]] · [[file:../../lowerers_spike/blend_harness.bl][Reference and harness]] · [[file:../../formal-logic/CORE-CONTRACTS.md][Returned value and named errors]]

2. *Enchant has already removed expensive redundant work and identified cases where reuse is wrong.* Sharing bounded reader output inside one Source snapshot reduced fresh preparation across 534 units from 998.6 to 553.9 seconds in one paired build. All 5,223 target files matched. The implementation replays guard accounting, checks loaded reader identities and publication epochs, and excludes failed parses. An unchanged SDK call and an incremental SDK production have quite different costs. Carry this discipline into editor compilation. A fast path that skips a fuel check, replays a macro effect, or reports the wrong source location changes the language. [[file:../../fresh-preparation/STATUS.org][Full build, controls and rejected experiments]]

3. *The strongest reason to use proof in the optimizer is a fact it otherwise loses.* Take opaque byte channels s and d in the same encoding, with straight byte coverage a. Define N = a·s + (255−a)·d. Independent interval bounds on the two products allow a sum of 130,050. The weights actually sum to 255, so N ≤ 65,025. This licenses a 16-bit unsigned numerator for every input. Lean checked that bound, the uniqueness of the author's floor law, and an alternative shift implementation including the bound on its intermediate sum. This is a theorem about integer expressions. The pinned C compiler, its vector instruction selection, and the CPU remain execution boundaries. [[file:../Alpha.lean][Universal argument and axiom audit]]

4. *An application law can permit the wrong picture.* Constant white passes the original brightness law. For alpha, exact endpoint laws alone accept an implementation that uses the destination until coverage reaches 255. Give the author an independent, readable requirement for every channel: the byte y must satisfy 255·y ≤ N < 255·(y+1). The endpoints follow, and interior rounding becomes an obligation. The existing camera worker declares premultiplied ARGB32 on an opaque background. Our proposed operation is two opaque buffers plus a separate coverage plane, evaluated in their declared byte encoding. A renderer adapter must establish this layout or select its existing implementation. Linear-light blending and general translucent RGBA composition require their own specifications. [[file:../../../examples/scene-renderer/camera_worker.py][Renderer pixel policy]] · [[file:../examples/wash.bl][Original wash]]

* How the compiler would work

** 1. Capture once and resolve ordinary calls

At save, the Source owner captures the selected export, exact source and include bytes, macro/provider identities, lexical and linked bindings, SDK and loaded compiler generation, and observed expansion inputs. Attach locations from this revision. Use the existing split between =compile.world/capture= and =prepare-captured= as the integration seam for its supported world profile. Route the renderer's ordinary entry through a checked compiler entry and verify the two paths resolve the same export. The contextual world, full language entry and sealed SDK have different coverage today. Do this comparison before transferring evidence between them. Read effects or dynamic calls whose dependencies cannot be sealed keep their existing evaluation/currentness checks. [[file:../../../priv/std/compile/world.bl][Capture and preparation]] · [[file:../../phase-compiler/NEXT-CUTOVER-ENTRY-POINTS.org][Entry points and qualification scope]] · [[file:../../../docs/compiler/generation.bl.org][Loaded compiler identities]]

** 2. Make the compiler's ANF the input to consumers

ANF already gives evaluation order, explicit intermediate values, resolved calls and links back to source. Produce an immutable per-definition view from it. Key the view by relevant resolved bindings, body, semantic profile and compiler pass versions. Analysis, ordinary BEAM lowering and candidate region extraction consume that same view. Keep exact source identity and diagnostics beside it. An unrelated comment can share work only once expansion establishes the same view and its relevant provenance assumptions hold. Debug locations and source-sensitive macros can observe such an edit.

Compute call dependencies once. Summarize effects, termination, argument and result representations, possible errors and ownership per definition; for a recursive group solve to a conservative fixed point or report unknown at the budget. Carry existing scope restrictions on ownership summaries. A dynamically resolved call stays generic unless its binding is guarded. The existing eligibility check already identifies effects, termination and result sort. Argument layouts, byte ranges, aliasing, bounds on work and exception behavior remain explicit admission questions. Remove the prototype's second source parser from the production path when the normal compiler can drive its positive and negative corpus. [[file:../../../priv/lib/native/eligible.bl][Eligibility verdict]] · [[file:../../phase-compiler/ownership-calls.bl.org][Context-sensitive ownership summaries]] · [[file:../region.py][Research parser to retire from this path]]

Schedule compilation by demand. For a save, start with the visible scene's selected export, declared law and already compiled dependencies. Index consumers by which answer they used: binding, interface, range, body or target artifact. Recompute the changed answer once. Stop propagating along a summary edge when the answer and its validity envelope are identical; an inlined body edge must still follow changed instructions. Discard obsolete diagnostics from cancelled generations. Share cheap structural traversals, then let expensive solver questions and target emission run only for reachable subjects. Batch independent obligations within one checker session, retain per-question identities and a clean-check replay, and measure queue contention before increasing concurrency. This makes compiler work proportional to an edit's affected *observations* where the dependency evidence permits it.

** 3. Check intent once per relevant meaning; check each transformation against that meaning

The author owns the law separately from the edit. From the selected ANF and its numeric/error profile, construct a formal subject using the existing obligation interface. Preserve the original question, premises, required rows, source positions and feasibility. Check certificates against the reconstructed subject. Use a warm checker for static lemmas about division, tiles and memory layout. Admit an instance only after checking its substitutions and premises. The author sees a counterexample, an unclosed obligation, or which assumptions discharged it. Set a policy for the admissible checker/axioms; record the checked claim and any remaining reviewed connection. The current proof-data checker already distinguishes a data connection from actual kernel execution. [[file:../../formal-logic/OBLIGATIONS.md][Closed obligations and trust boundary]] · [[file:../../formal-logic/FLOAT-SOURCE.md][Numeric mismatch in compiled execution]]

For performance-critical code, extract a kernel region from ANF with immutable input views, explicit shapes/strides, a fresh output and a known consumer. Select transformations such as narrowing, loop fusion and SIMD. Each transformation supplies a rule identifier and its concrete premises, or a translation-validation question relating its before/after region. Validate return and error behavior as well as the values stored. Establish size arithmetic and aliasing at entry, before writes. Choose a safe generic route for overlapping views or unsupported layouts. Preserve traps and effect order on branches. A partial order of independent tiles allows a target to schedule work freely. A quantization step between layers remains observable even when both layers become one loop. [[file:../../../docs/native-regions/04-boundaries-and-lifetimes.typ][Boundaries and lifetimes]] · [[file:../Tiles.lean][Existing tile model]]

Keep one independent path. The ordinary compiled BL export supplies examples and differential outputs. The law has a human-owned definition. A lowerer-derived oracle alone can reproduce the same mistake twice. On tiny exhausted domains retain exhaustive checking; on compositing use the algebraic law and translation checks, then exercise emitted binaries on adversarial layouts, aliasing, empty/tail tiles and actual devices. A changed emitter reopens that bridge. A checked model, a byte-equivalence test and a machine-code preservation theorem are three different entries on the receipt.

** 4. Plan placement for a chain of operations

Expose immutable shape, byte encoding, residency, consumers, work and any host-observable intermediate. A scalar function can participate in a contiguous CPU SIMD loop or in a GPU pass that consumes an existing texture. Fuse two passes when the intermediate has one compatible consumer, the schedule preserves both rounding points and exceptions, and there is no observable intermediate publication. Reuse an already compiled generic variant until enough work amortizes specialization. Bound the number and memory footprint of variants. Try a constant-alpha specialization only if that parameter is stable and measured savings cover its cost. Bind its value at dispatch.

Estimate and then sample queue delay, transfer, launch, execution, synchronization and delivery to the next consumer. Keep measured costs in a device/driver/layout-specific record, independently of the proof. For specialization, estimate how many calls this revision will actually serve. If a variant costs C extra time to qualify and saves S per call including transfers, it needs more than C/S calls to pay back that preparation when S is positive. Treat this as a planning heuristic: background preparation also competes for cores and memory with the foreground edit. An operation with a frame deadline needs a tail-latency gate regardless of amortized throughput.

A busy GPU, a disconnected device or a new host consumer may select a different legal route without changing the law. Recheck the launch descriptor at dispatch. A pure operation with private partial output may discard it and retry a qualified CPU route. Retrying effects needs a separate application protocol. Measure BEAM scheduler latency while work runs. ** 5. Let the running owner publish and retire

Prepare outside the serving environment. Once required application obligations close and the ordinary artifact passes its declared checks, offer the candidate to the actual Source owner. It compares the expected parent and latest requested generation, then selects an immutable revision in one publication decision. Failure, cancellation or an older candidate finishing last leaves the accepted pointer alone. Optional acceleration may join a still-current revision later if its precise subject, target and guards match. Record per invocation which variant really ran. If a capability is a required application contract, the owner waits for that evidence before activation.

A request borrows its revision and resources at dispatch. CPU completion or a GPU fence ends the borrow after the last consumer, even on cancellation. A request can return its own old result to a caller that asked for that revision. Updating a “latest frame” additionally requires the current revision and frame/request sequence. Two frames from the same revision can finish out of order. Keep input data basis, revision, law and output together. On restart recover the last fully committed bundle and revalidate target compatibility before selecting an accelerator. Bound retained generations, stop admitting new speculation under pressure, and expose the oldest outstanding lease. The existing Env and immutable runtime modules demonstrate coexistence; device-fence and crash-recovery integration are proposed work. Use Datom to record accepted decisions and explain them later. Per-frame lookup and kernel dispatch should use a held immutable handle. [[file:../../phase-compiler/runtime-revisions.bl.org][Physical revisions and Env fences]] · [[file:../../formal-logic/SELECTED-RUNTIME.md][Selected runtime observations]] · [[file:../evidence/exercise.json][Rehearsed stale-completion control]]

Stateful changes need another decision at the same owner. The compositor keeps the image and actor-state shape compatible. If an edit changes an actor's mailbox protocol, persisted schema or an external effect, capture the compatibility or migration contract, stage it with the revision, and choose a cutover point that handles already accepted messages. A pointer rollback restores code; undoing externally visible writes needs an application-defined recovery operation. The first implementation should exercise a compatible code-only edit and explicitly refuse an incompatible state change missing its migration. * What really has to be recomputed?

#+begin_rosetta
Change | Work that can survive | What must be established again
Comment or source location | Semantic analysis, law and machine variant if resolved meaning and dependencies agree | Exact Source revision, attribution, expansion observations, current request
Helper body | Unaffected definitions and general lemmas | Changed behavior, its law instances, inlined callers and variants; indirect callers recheck relied-on summaries and bind the intended revision
Law or permitted checker assumptions | Existing ordinary artifact when code is identical | Required questions, affected evidence and admission under the new policy; a matching binary cannot admit itself
Layout, aliasing or input dimensions | Code for a guarded family, scalar semantic law | Shape, bounds, overlap, ownership, transfer cost and guards for this request
Lowerer, compiler generation or target ABI | Independent mathematical lemmas under compatible checker identities | Affected transformations, executable artifact and compatibility, differential and dispatch evidence
Device occupancy or thermal state | All current semantic evidence and compatible binaries | Placement sample and request decision
#+end_rosetta

Keep the captured provenance, subject, obligation, target artifact and runtime generation as separately keyed records linked by dependency edges. A certificate cache hit is only an offer to the checker. A profiling hit can change a choice among already legal variants. An exact executable can serve two revisions whose observable contract and attribution differ, provided each revision earned admission independently. Deduplicate concurrent preparation by exact key, keep speculative outputs unpublished, recheck inputs/currentness at commit, and evict unleased work by budget. Those distinctions prevent both needless recomputation and a stale proof authorizing a new program. * The experiment that changed our lowering recommendation

We tested two successive alpha layers. Each input is a plane of bytes in CPU memory with its own per-pixel coverage. Each stage rounds down. Materializing the intermediate writes and rereads one byte per pixel between passes. Fusion keeps that byte in a lane, including its rounding. We crossed this decision with three arithmetic forms: ordinary unsigned arithmetic, a proved 16-bit numerator followed by division by 255, and the proved 16-bit add/shift implementation. The proof says which forms are lawful. The backend and measurements decide which to use.

| Single-thread CPU, median per two-layer frame | Materialized, wide | Fused, wide | Materialized, 16-bit quotient | Fused, 16-bit quotient | Materialized, 16-bit shifts | Fused, 16-bit shifts |
|-----------------------------------------------+--------------------+-------------+------------------------------+------------------------+----------------------------+----------------------|
| 129×73, µs | 5.395 | 4.977 | 2.011 | 1.675 | 2.241 | 1.854 |
| 1920×1080, ms | 1.654 | 1.334 | 1.124 | 0.714 | 1.247 | 0.750 |

On the i7-10700, the best measured large-frame variant processed 2.32× as many pixels per second as the materialized wide baseline (1.654/0.714). The compact quotient also beat the explicit shift rule at both sizes in this run. GCC reported vectorizing the loops. This supports conveying a proven range to the backend and keeping profitability target-specific. The candidates are handwritten representations of prospective compiler output. This run measures single-channel CPU execution from preallocated memory, excluding allocation, compilation, qualification, transfer and readback. It supplies no Enchant/Bend alpha ranking. Twelve rotating-order rounds, one warmup, complete byte comparisons after timing, shared machine. [[file:../comparison/alpha-fusion.c][Six measured variants and independent reference]] · [[file:../evidence/alpha-fusion.json][All samples, pins, source hashes and vectorizer report]]

#+begin_src beam-lisp :id alpha-author-controls
(let [mix (fn [s d a] (quot (+ (* a s) (* (- 255 a) d)) 255))
      admits (fn [s d a y]
               (let [n (+ (* a s) (* (- 255 a) d))]
                 (and (<= (* 255 y) n) (< n (* 255 (+ y 1))))))
      first-byte (mix 2 0 127)
      fused (mix 2 first-byte 127)
      delayed (quot (+ (* 127 2 255) (* 128 127 2)) (* 255 255))
      signed-shortcut (+ 1 (quot (* 1 (- 0 1)) 255))]
  (assert (= [17 201] [(mix 201 17 0) (mix 201 17 255)]))
  (assert (admits 255 0 128 128))
  (assert (not (admits 255 0 128 0)))
  (assert (= [0 1] [fused delayed]))
  (assert (= [0 1] [(mix 0 1 1) signed-shortcut]))
  {:retained-rounding fused :delayed-rounding delayed
   :source-darkening (mix 0 1 1) :signed-shortcut signed-shortcut})
#+end_src

The signed shortcut uses truncation toward zero on a negative difference. The delayed-rounding mutant keeps more precision and still produces the wrong program. Keep both witnesses as optimizer regressions. In the production pass, drive them through the original BL export and each emitted variant. * What would count as surpassing Bend?

Bend 2 uses explicit fork/join structure and ownership to run the same computational segments across CPU and GPU. Its proof workflow gives authors a readable law and a second checker for BendTT. Its documentation scopes the source translation and native runtime separately. Enchant can aim for stronger coverage of a *particular* source-to-serving path and shorter time for a *particular* change. Neither a new IR nor a language-wide claim of superiority settles those comparisons. Bend won our earlier fresh-process wash on one CPU thread, 13.13 ms versus 90.72 ms for the prepared Enchant Python wrapper. That experiment also measured Bend compilation separately. * Order of implementation and conditions for moving on

1. *One normal renderer entry and its real owner.* Start with the existing byte blend, an independently written law and a small adapter for opaque images with separate coverage. Use ordinary BL for the baseline. Check returned layout, named shape errors, exact old/new export behavior, busy-reader continuity, a broken edit and a stale completion. Pass when a second author can change the helper through the normal application entry without modifying a research parser, proof generator or shader. If this fails, fix the source/owner connection first.
2. *Reuse just the work the evidence permits.* Instrument an untouched save, comment, helper, law, compiler/rule change and ABI change. Record cache hits by subject and a reason for each miss. Compare cold and warm results, bytes, errors and witnesses. Force stale and corrupted entries. A warm path must produce the same admissibility decision as a fresh independent run. Validate memory bounds under rapid edits and continued scheduler responsiveness.
3. *Use facts to earn the first automatic CPU variant.* Extract the actual returns and memory effects from resolved ANF, check correlated byte bounds and fresh output, preserve both rounding points, and select widths through a costed rule. Compare the emitted variant to these six controls. Force the forbidden rewrites. Continue when a different author can express a sibling operation with the same rules and no special name or descriptor.
4. *Put placement and the comparison under load.* Keep two real passes resident on the same device, add host readback and device-loss controls, retire after the fence, and qualify the same selected source under concurrent edits. Run the paired Bend protocol. Publish a win only for the dimensions that improve at the matched guarantee and cost boundary. Preserve a slower or failing comparison in the journal.
