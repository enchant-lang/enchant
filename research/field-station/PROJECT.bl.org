* What we are building
#+begin_lede
Edit ordinary Enchant code, inspect one deployment plan, watch real progress,
and get an accurate result. The same service identity follows a preview into
shared use, across hot publication, reboot, backup and restore.
#+end_lede

Use Enchant's existing Datom, proc, checked namespaces, native Nix codec,
reload and logic libraries. Extend Foundry's existing definition, admission,
engine, journal, control and host integration. Do not create a second actor
framework, deployment state machine, authoritative UI database or SQL adapter.
Promote stable compositions upstream, with coherent commits and focused checks.

* The starting evidence
[[file:prototypes/evidence/acceptance.org][The prototype acceptance record]] qualifies a source-generation handover,
old WebSocket continuity, 5,156 successful HTTP observations and cold-process
journal recovery. It does not qualify a packaged workstation controller,
booted NixOS installation, cross-runtime writer transfer or production migration.
Keep its immutable SDK for project checks; batch actual runtime changes before
one SDK build. Do not relabel historical receipts as checks of new code.

* Ownership that can be explained
#+begin_rosetta
Resource | Owner | What the other layers may do
Accounts, privilege, directories, packages | NixOS | Request a reviewed infrastructure transition.
Controller process | systemd | Start it, observe it and restart after crash.
Application generations | Foundry | Admit, publish, drain and recover through the existing engine.
Persistent store | One station resource owner | Generations borrow it; retirement releases borrowing.
Accepted work and external processes | Proc lifetime scope | Cancel or drain under explicit deadlines and capacity.
Public connection routing | Stable ingress | Route to an admitted runtime; enforce trusted identity.
#+end_rosetta

A successful Nix activation is one receipt. Deployment success also needs the
expected application generation through the real route and completed retirement.
Serving, operation completion and cleanup remain separately visible facts.
Unknown effect outcomes require reconciliation, never blind replay.

* Integration discipline
Commit coherent work on main before checks. Reuse the qualified immutable SDK
for project-level changes. Batch any upstream language/native changes before
one build, then run focused checks against that exact artifact. Preserve other
writers' changes. Stop only processes owned by these checks. Keep progress,
public receipts and private diagnostics separate.

The roster describes the complete migration; individual completed tasks do not
mean production is already switched. Changes to production begin only after
the relevant migration, continuity and recovery gates have passed.
