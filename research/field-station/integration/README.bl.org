#+title: Native workstation integration checkpoint
#+date: 2026-11-16
#+status: Committed on main; booted NixOS qualification in progress; no production activation

* What is implemented
The existing Foundry upgrade engine, journal and control observations now feed
bounded coalesced CLI progress. JSON stdout remains usable; progress goes to
stderr. Source publication is distinct from drain completion and uncertain
outcomes never become successful deployments.

A sealed online definition supplies an ownership explanation: keep the
controller, borrow existing store writers, show declared migrations and app
borrowing, publish the router, then drain the previous generation. Its digest
is part of the reviewed plan and is rechecked before submission. Host/runtime
replacement has a separate availability contract.

One native host-assets inventory now drives host rendering, managed release
packaging and a generated pure Nix projection. Dependency closure checks caught
previously missing initialization, discovery, preparation and recovery files.
The installed helper package verifies the native inventory it actually carries.

The immutable station-controller package composes the existing lifecycle with
one explicitly selected runtime. It starts from / and has no checkout path or
Python message bridge. Two cold OS processes passed actual HTTP and stopped
writer/reopen checks. The newer package uses native systemd notification and
finite bootstrap failure stages; those have focused native and module checks.

The Foundry host module now accepts online.controller and
online.candidateArtifacts. Candidate closure retention does not change the
unit. A controller package change explicitly restarts it. systemd credentials
keep the root-owned original config separate from the app's private copy.
HTTP startup readiness remains required after native notification. The credential
adapter pins the actual kernel cgroup unit and effective UID; it supports
systemd's root-owned read-only credential with its kernel-enforced named-user ACL.
It never accepts a directory merely because an environment variable names it.

Receipts bind their original revisions and exact scope. Earlier successful
checks are not relabelled as checks of later source. Raw traces stay in private
temporary directories. The booted NixOS gate has not passed yet: its real
credential delivery now passes the private adapter; startup selection ownership
is being qualified with root-owned immutable releases and app-owned state.

* Daily use this enables
A deploy can explain what stays alive and what actually restarts, show why it
is waiting, and fail when startup or retirement is incomplete. Installed
packages no longer depend on a developer checkout to supply missing framework
files. A workstation restart has an explicit selected runtime and recoverable
application journal instead of ambient shell settings.

The complete [[file:../PROJECT.bl.org][implementation roster]] still owns the wider migration. Production runtime
attestation, process handover, complete messages migration and replacement of
the remaining Python helpers are not claimed complete by this checkpoint.
