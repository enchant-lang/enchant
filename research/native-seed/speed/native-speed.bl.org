* In one breath
#+begin_lede
The original native seed ran a compiler and runtime written in BEAM's
vocabulary on a Scheme host. Primitive type tests, equality and sibling
calls crossed that host boundary. Early local experiments each moved the
whole pipeline by 0–10%.

Wave 1 of round 3 rebuilds the 34-namespace compiler from Source. Its
native stage2 and stage3 match byte for byte. The archived six-form warm
pipeline takes 8.11 ms on native and 1.73 ms on BEAM.
Linking, the BL kernel, and compiled control flow account for much of the
change from the original baseline below. The integration review records
the remaining qualification and performance work.
#+end_lede

#+end_stats

* Words this dossier leans on
#+begin_terms
Native seed | BL → Scheme (BL-owned emitter =src/native/scheme.bl=) → Gambit 4.9.5 → C → ELF. Self-hosted: stage 2 = stage 3 byte for byte.
Remote | An ANF =:remote= node: a call to =Module/fun/arity=. BEAM compiles it to a call instruction or a guard; the seed resolves it by string at runtime.
Leaf | A host procedure standing in for a BEAM BIF or Elixir function (=host/host-leaves.scm=, 433 of them).
Toll | Fixed per-operation overhead independent of the work done: lookup, wrapper, list consing, =apply=, emulated type test.
Kernel | The small set of primitives BL semantics is written against. Today: BEAM's. Proposed: BL's own, with one implementation per backend.
Hard cutover | The old path is deleted in the same change, not kept behind a flag.
Warm-core benchmark | Six macro-free Source forms read, compiled and emitted twenty times per sample, nine samples, in one warm process on each side (=benchmark/=).
#+end_terms

#+begin_honest :title "What this is not"
Not a claim that BEAM is slow or that Gambit is fast. The comparison is the same
Source, the same macros, the same ANF boundary and the same emitter on the same
hardware; process start, file IO, macro installation and C compilation are
excluded on both sides.
#+end_honest

* Why the native seed is slower
** The arithmetic already closes most of the gap
The dossier for the native seed recorded the counts and the micro-costs
separately and concluded that counts alone do not attribute the gap. Multiplied
together they do, to first order:

* Seven step changes
Each change removes a whole category of bugs, not only a cost. The first four
are being implemented now; the last three are the next round (see the roster).

#+begin_principles
Link once | Every statically known target becomes a direct Scheme reference at build time. Globals are Gambit cells, so redefinition writes the cell. Deletes the epoch roots, identity caches, availability caches and wrappers. Bug class removed: stale-cache and epoch bugs. Cost: ~300 ns → a few ns per call.
BL owns its kernel | About sixty primitives (kind, =, compare, first/rest/nth, get/assoc, invoke, raise, cons) specified once and implemented per backend. BEAM lowers =kind= to guards; native to a tag switch. This round: inline BIF templates and native kernel overrides that delegate every uncovered case to the compiled BL body. Bug class removed: backend parity drift — the Decimal equality, negative-divisor modulus and ETF identity bugs formal-logic found were all this class.
Values designed for BL | This round: allocation-free keyword comparison, eq pre-scans in small maps, same-kind fast paths, order-identical results. Next: tagged immediates, interned keywords with id and hash, one header word with kind, arity and metadata, metadata out of wrapper tuples. Bug class removed: representation ambiguity (nil/false/(), struct-as-map, meta-wrapper-as-tuple).
Compile control, never interpret it | Every pattern kind becomes decision code; fixed formals per arity; =case= matches its subject directly; total guards skip the exception catcher; inline truthiness; direct loops and integer lowering by default. Bug class removed: the direct and generic matchers drifting apart, and exponential clause duplication.
Formal Core as the middle end | The elaborator produces typed Core with facts — Int, kind, purity, non-escape, ranked termination — and the emitter consumes them. Rewrite rules are proved once in Lean and applied freely, with no solver in the compile loop. Bug class removed: optimisations that miscompile; ends the byte-parity dossier per micro-experiment.
Ticks and frames off the hot path | Budget checks only at loop back-edges and unknown calls; source frames from return-address tables rather than a dynamic parameter per call; debug and release share code shape. Bug class removed: observers that change the program.
Two compile tiers | Edit loop: Core → closures in microseconds, no gsc/clang. Release: Core → C per function, content-addressed in the existing unit store. Emit structured forms, not 4.37 MB of concatenated text. Makes <1 s edit-to-test a property of the design and deletes the 256 KB chunking.
#+end_principles

* Where the big-O changes are
The seven step changes remove per-operation tolls. This section asks a
different question of the whole pipeline: where does cost grow faster than
the input, and where is a constant so large that a different algorithm is
orders of magnitude away? It was answered in three passes. The =codebase=
fact store, over all 20 sources stage 1 runs, proposed candidates. Scaling
runs on BEAM measured the exponents. =eprof= and =system.incr= named the
causes.

#+begin_stats
2.0 | slope of emit on nested functions | quadratic: 1,024 levels emit in 7.9 s, compile in 20 ms
~83% | of that emit inside the lazy-cell walk | =BeamLisp.LazyMemo.deps_walk=, 20.9 M calls at 256 levels
~250 | function calls per source byte, reader | 2.9 M calls for 11.4 KB; ≈1.3 µs per byte on BEAM
12 of 67 | definitions whose identity changes on an unchanged re-analysis | =native.scheme=, via =system.incr/fn-identity=
#+end_stats

** M · A lazy cell walks everything it captures
Every lazy-sequence cell runs a walk proportional to the values its thunk
captures. On BEAM, =priv/host/lazy_memo.bl= walks the closure environment at
create time and the value at publish time. On native,
=native-lazy-publish= in =host/host-lazy.scm= walks every published value. In
both cases the purpose is the memo graph's =would_cycle= edges.

An ANF node has fewer than eight keys, so the clean-value memo never
remembers one. Each nesting level that builds a lazy sequence therefore walks
its whole subtree again. Emit on nested functions has a slope of 1.95–2.06,
and the walk with its predicates and map folds is ~83% of that emit. On
real, shallow definitions from =reader.bl= it is ~20% of emit.

Both runtimes already blackhole a running cell: a re-entrant force fails with
=recursive_force=. Detecting cycles at force time, and between processes only
when a force blocks, makes the edges unnecessary.
- Per-cell cost goes from O(captured) to O(1), and emit goes from
  O(size × depth) to O(size), for every BL program, not only the compiler.
- Deleted with it: the dependency walk, the bounded identity memo of clean
  values, the NIF's edge union and cycle check, and the publication walk.
  That is a second, approximate model of reachability which must otherwise
  stay in agreement with the real one.

** D · Compiled code depends on what the VM has loaded
=system.incr/fn-identity= over =src/native/scheme.bl= gives a new identity to
12 of 67 definitions when the unchanged source is analyzed a second time.
A comment-only edit changes the same 12, and a one-body edit changes those 12
plus the edited one. All 12 call through the =string/= alias. Before
=clojure.string= is loaded, such a call compiles to an exact =:invoke=; after,
it compiles to =(do (Loader/ensure_ready "clojure.string") …)=.
=reset-fresh!= does not change this.

The fix is to resolve aliases from the namespace header's declared
requirements, never from VM state, and to make readiness a link-time fact.
Compilation then becomes a function of the source and its declared
interfaces. That removes the "same source, different artifact" class of bug,
and it is the precondition for U: a body's identity becomes a sound cache key
for the unit store, the chunk store and incremental analysis.

** R · The reader spends ~250 calls per byte
The reader is linear but slow: about 1.3 µs per byte on BEAM, and native read
is a further 15.5× slower. The read cone's static fan-in is led by equality (151
sites), =first= (69), =rest= (50) and =empty?= (43). =eprof= agrees: 116 k
=eqv=, 104 k =compare= and 86 k =empty-list?= calls for 11.4 KB.

The source is an Erlang charlist. Each character is classified by a chain of
generic equality tests, each going through =rt='s kind dispatch, and a
four-field position tuple is rebuilt per token.

The replacement is a byte-class automaton over the UTF-8 binary:
- one 256-slot class table, so dispatch is a small-integer =case= (a jump
  table on both backends);
- tokens are binary slices;
- the position is an offset plus a line counter, with columns derived only
  when a diagnostic asks for them.

The estimate is 20–50 ns per byte, 25–60× on BEAM. It is not measured yet.
On native it also removes most of the generic-equality traffic that K
currently absorbs.

** U · A one-definition edit rebuilds most of stage 1
The full stage-1 build breaks down as:

| Step | Time |
|---|---|
| Emitting 55 chunks (content-addressed, so unchanged chunks are reused) | ~30 s |
| Splitting =stage1.scm= | ~35 s |
| Twenty gsc → C → object units | ~2 min |

The split greedily packs consecutive top-level forms into 256 KB units:
=split-stage1.log= shows 19 cuts between 228 and 262 KB. Any size change in
one form moves every later boundary, so on average half the units recompile.

The fix is to cut units by content (one unit per namespace chunk, or
content-defined cut points) and key each unit by its own bytes, with the link
table separate. Rebuild cost becomes proportional to the change: one edit
recompiles one unit, about 6 s. With G's closure tier on top, the edit loop
is milliseconds, two to four orders of magnitude.

** T · BEAM pays its own invocation toll
In every compile profile, the top self-time entries are =Env.source_head=,
=function_exported/3=, =ets:whereis=, =ets:lookup= and =persistent_term:get=.
Each runs about once per higher-order invocation, through =call-invoke= and
=check_source_invocation!=, and together they are ~20% of compile. This is
the BEAM twin of the =native-remote= toll that L removed, and link-time
resolution removes it the same way. It is a constant factor, about 1.25×,
not an order of magnitude.

#+begin_src beam-lisp :id bigo
;; speed/bigo/scaling.txt: BEAM microseconds per call, one shape grown per family.
(def emit-rows {:deep-fn [[64 30641] [256 455906] [1024 7930886]]
           :deep-if [[64 2028] [256 5775] [1024 20726] [2048 42185]]
           :wide-call [[64 3376] [256 9986] [1024 31672] [2048 55023]]})
(def compile-rows {:wide-let [[64 866] [2048 20419]] :deep-if [[64 288] [2048 8778]]})
(def read-forms [[1343 2921] [43007 53016]]) ; [bytes us]
(defn slope [[n0 t0] [n1 t1]] (Float/round (/ (math/log (/ t1 t0)) (math/log (/ n1 n0))) 2))
(defn slopes [rows] (mapv slope rows (rest rows)))
(def emit-slopes (into {} (map (fn [[k rows]] [k (slopes rows)]) emit-rows)))
(def compile-slopes (into {} (map (fn [[k rows]] [k (slopes rows)]) compile-rows)))
(assert (every? #(> % 1.8) (:deep-fn emit-slopes)))
(assert (every? #(< % 1.2) (concat (:deep-if emit-slopes) (:wide-call emit-slopes))))
(assert (every? #(< % 1.2) (mapcat val compile-slopes)))
{:emit emit-slopes :compile compile-slopes
 :read-us-per-byte (Float/round (/ (second (last read-forms)) (first (last read-forms))) 2)}
#+end_src

#+begin_honest :title "What the static facts did and did not find"
The =codebase= store over-reports. It lists 145 calls to linear-cost
operations inside per-element loops and 1,059 inside recursive functions in
the three hot cones. None of the shapes they suggest grows faster than linear
up to n = 2048: wide =let=, deep =let=, deep =if= and wide calls all stay at
slopes of 0.6–1.25. None of them is a big-O problem today.

The quadratic came from a runtime the facts cannot see: =LazyMemo= is host
code below the language. The facts were most useful for scoping the work:
- the size of each cone (read 103, compile 324, emit 69 functions);
- the fan-in that pointed at the reader's character dispatch;
- the recursion ranking that put =native.scheme/emit= and =anf/node-ok?= first.

Also checked and fine:
- Native maps are flat and sorted up to 16 keys, then AVL, so O(log n).
- The require graph has 31 edges and no cycles.
- Nested =str= emission copies O(size × depth) bytes but stays under 10% at
  depth 2048.
#+end_honest

#+begin_honest :title "Limits of the logic layer met on the way"
Indexing the 20 sources (about 18 k lines, 1,387 functions) took about two
minutes, roughly 6.6 ms per line. One 5 k-call transaction exceeded the 30 s
writer call, so the index is transacted in batches of 1,000. The walker
crashes on =core.bl='s own macro definitions, so that file is indexed one
form at a time. =loop=/=recur= is not a loop head, and =:call/cost-coverage
"recursive"= marks 675 functions, too coarse to rank by. These are the next
things to fix if the fact store is to answer cost questions alone.

Workstreams L, K, V and C are integrated. M and D are the next round's first

** DONE L · Link once
:PROPERTIES:
:AREA: linking
:OWNER: agent
:PROTO: research/native-seed/speed/link
:END:
*Owns* =chunks.bl=, =eval.bl=, =bootstrap.bl=, =host-compiler.scm=, leaf
binding forms in =host-leaves.scm=, the registry section of =host-values.scm=,
and the call-protocol functions of =scheme.bl=.
*Approach.* Use the decisions =chunks.bl= already computes. Compiled targets
become direct references to =native.bootstrap/binding-name=; =$blfn=
definitions publish one binding per arity and a variadic arm; leaves get stable
named bindings; globals link directly with =$macro= unwrapping decided
statically where possible. A setter per linked definition keeps runtime
redefinition observable. An unknown callee takes =(if (procedure? f) (f a …)
(bl-invoke f …))=. Arithmetic stops allocating a closure per operation. The
kernel hooks are called here.
*Deletes* the epoch roots, identity cache, availability cache and wrappers,
and the fixtures that asserted them.
*Checks* host fixtures in gsi; emission of a few real definitions over the
captured closure; a gsi program for direct calls, arity entries, the variadic
arm, redefinition, macro unwrap and the invoke fast path.

* Questions
#+begin_ask :id Q1 :title "Is map iteration order part of the language?" :options "Yes, Erlang term order|No, unspecified; canonical only through formal identity|Insertion order" :answer "No, unspecified; canonical only through formal identity" :note "Whatever is fastest, fuck it." :at "2026-11-17 10:54" :by timinou
Today native maps reproduce Erlang term order exactly. That keeps emitted bytes
identical across backends, but it forbids hash maps natively. BEAM itself
switches from sorted to hash order above 32 keys, so programs that depend on
it are already fragile.
#+end_ask

The kernel is the boundary every backend implements. Putting it in the formal
