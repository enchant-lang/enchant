* The destination
#+begin_lede
Develop BL's compiler and proc/actor programs with a warm native BL tool.
Get source-level errors, run tests, reload compiled code and package a program
through one familiar workflow. Ordinary use should run without BEAM.

The next release earns its place through measured speed against warm BEAM,
usable diagnostics and real project work. The 18 compiler namespaces are one
enabling milestone in that delivery.
#+end_lede

#+begin_decision :id native-devtool-first :title "Native BL development tool first" :status decided :answer "Native BL development tool first" :by "conversation"
- [x] Compiler and proc/actor development drive the first usable release.
- [ ] Native application deployment drives the first release.
Keep BL → Scheme → Gambit → C as the production route. Deployment follows
from the same pipeline. Reuse BL's planner, Source worlds, unit store and
session policy; adapt their host boundaries for native execution.
#+end_decision

#+begin_honest :title "Behavior passes; the speed thesis is not proved"
The one-switch prototype preserves reader results and diagnostics, final Scheme
bytes, live calls, captured closures through GC, refusal before publication and
rollback. It compiles 12 pattern clauses and captures 172 primitive call sites.
But this parse never runs the general matcher. Only 2,493 remote resolutions
vanish; shared runtime code retains the other 106,443. Allocation does not fall.
The 4% pipeline movement is insufficient to establish a useful gain on this
shared host. Keep :reference as the default. A broad cutover is not justified.
#+end_honest

The mode belongs to the existing native AOT adapter, not a new compiler path.
Opt in with =:emission-mode :specialize-v1=; the serial runtime boundary checks
the artifact's exported =primitive-check= before activation and requests.
Production generation custody, concurrent publication and all pattern/actor
shapes remain outside this prototype's qualification.

Reproduce with =python3 research/native-seed/cutover/run.py research/native-seed/out/cutover-fresh=.
The command reuses the pinned SDK and compiler image. Retained artifacts can
be remeasured without compilation by passing their existing output directory.

* What will count as faster?
#+begin_honest :title "The seed has not earned the speed gate"
The first matched warm core diagnostic is 35.01× slower than BEAM. Both
produce identical Scheme bytes. This is the current correctness seed, with
all C objects built at -O0, omitted shared optimization and heavy generic-call
traffic. Attribution is still incomplete. It is not an acceptable performance
result for the daily tool.
#+end_honest

Read → compile → emit | 132.716 | 3.791 | 35.01×
#+end_rosetta

Each number is the median of nine batch averages, twenty operations per
batch, after warmup in one process per runtime. Same 471-byte macro-free
Source, :js ANF boundary, attribution and emitter options; no result cache.
Startup, macro execution and native backend compilation are excluded. This
small diagnostic locates costs; it does not ratify the product's speed goals.

The first counter pass records 106,933 remote calls for one parse, including
19,813 raw equality calls. The compiled-call interception control passed and
output bytes stayed identical. Counts are instrumentation, not timings.
The separate BEAM control enters rt/eqv and rt/k-eqv 4,092 times and
rt/k-compare 3,612 times, exactly matching native. These common helpers have
the same call counts; the large execution-cost gap needs work below them.
