* The destination
#+begin_lede
Develop BL's compiler and proc/actor programs with a warm native BL tool.
Get source-level errors, run tests, reload compiled code and package a program
through one familiar workflow. Ordinary use should run without BEAM.

The next release earns its place through measured speed against warm BEAM,
usable diagnostics and real project work. The 18 compiler namespaces are one
enabling milestone in that delivery.
#+end_lede

#+begin_decision :id native-devtool-first :title "Native BL development tool first" :status decided :answer "Native BL development tool first" :by "conversation"
- [x] Compiler and proc/actor development drive the first usable release.
- [ ] Native application deployment drives the first release.
Keep BL → Scheme → Gambit → C as the production route. Deployment follows
from the same pipeline. Reuse BL's planner, Source worlds, unit store and
session policy; adapt their host boundaries for native execution.
#+end_decision

#+begin_sequence :title "The development loop we are building"
lanes You · editor / CLI | BL · warm native compiler | Program · compiled native BL
You -> BL : edit a function
BL -> BL : select affected units with the existing planner
BL --> You : source diagnostic or successful compilation
You -> BL : run the relevant tests
BL => Program : load compiled units; preserve valid running work
Program --> You : results, source stack or running actor service
#+end_sequence

* What will count as faster?
#+begin_honest :title "A speed win over BEAM is still to be measured"
The checked 3.752 s cold / 1.570 s warm result covers a two-function,
BEAM-coordinated native-module prototype. Full native self-emission takes
200.642 / 211.299 s. A matched native-versus-warm-BEAM comparison is pending.
#+end_honest

#+begin_rosetta
Metric | Working target — provisional | Measurement contract
Compiler frontend | At least 3× warm BEAM throughput | Same Source, macros, ANF boundary, hardware and cache state; count real work on both sides.
Unchanged development request | Under 100 ms | Persistent native compiler; zero Source preparation, Scheme emission or C compiler jobs.
Small body edit → test result | Under 1 s | Include invalidation, preparation, Scheme emission, Gambit/C work, loading and relevant tests.
Usability and resources | Source errors, cancellation and bounded retained state | Record median / p95 latency, peak / steady memory, allocation and GC; check repeated edits and failed builds.
#+end_rosetta

These are proposed engineering targets to ratify against the baseline. Record
frontend work and end-to-end delivery separately. Use the existing warm BEAM
path with equivalent reuse; record cold startup separately. Source, macro,
interface and compiler/emitter changes get separate cases. Broad invalidation
remains correct when compiler identity or dependencies require it.

#+begin_decision :id use-jolt :title "Borrow the design; keep bl-ANF" :status decided :answer "Agree" :by "conversation"

- [ ] Translate BL into Jolt's Clojure frontend or its different IR.
Jolt does not consume bl-ANF. Reusing its complete runtime would require a
value/namespace/callable compatibility layer. The existing BL compiler and
JavaScript actor kernel already define the semantics we need.
