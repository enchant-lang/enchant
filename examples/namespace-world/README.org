#+title: Authenticated namespaces: five executable sets

This is the language integration of the service-world prototype. All reusable
code lives in priv/lib/auth and priv/lib/veritas/assurance.bl. Normal command
startup reads :auth/imports and :auth/realms in env.bl, checks the provider, and
installs ordinary namespace vars before compiling application code. No generated
namespace source or application RPC wrapper is needed.

Exact SDK pins and completed native, cross-VM and application checks are recorded
in [[file:../../research/service-world/evidence/native-namespaces-qualification.json][the qualification record]].

Run all ten examples in one VM with the qualified checkout runtime:

#+begin_src sh
cd examples/namespace-world
../../bin/bl --cold run check.bl
#+end_src

The trusted example.entry host fixture supplies an already-verified person.
It is a test fixture, not a login method. Actual host ingress uses auth.ingress
and verifies the connecting gateway or a configured auth verifier. The app sees
only world.catalog; external identities, issuer files and routing are host data.

The provider's [[file:provider/src/example/catalog.bl][namespace]] owns exports,
application grants, role requirements, resource identity and effect budgets.
Its [[file:provider/env.bl][environment]] binds the trusted example.host factory.
The factory and its dependencies resolve from the provider's own source paths.
The consumer's [[file:env.bl][environment]] binds a logical namespace to that realm.
The protected body receives finite resource-port data, never a filesystem path,
credential or unrestricted host callback.

For remote placement, publish an interface with auth.contract/publish! and use
:transport :remote with :interface, :world, :url and :issuer-public. The interface
artifact is bounded operator-supplied data with a canonical namespace/version/
arity fingerprint; it is not an authorization receipt. Both ends compare that
fingerprint. Local and remote invocation share the finite-data dispatcher.
Wire protocol 2 rejects old or mismatched interface shapes explicitly. Remote
credentials use TLS by default. The isolated two-VM fixture explicitly enables
:allow-loopback-http? for its temporary 127.0.0.1 listener; that option provides
no protection against a hostile local listener and is for controlled tests.

A host can configure :delegation {:issuer-file ... :authority-file ...
:application ... :world ... :namespace ... :exports #{"services-in"}} on the
remote realm. The broker requires the current verified subject/application and
current resource membership, and issues a short-lived token for one operation
on one resource. A person cannot borrow another person's token. The receiver
independently rechecks signature, audience, expiry, revocation and fresh roles.
The issuer remains private host state. No secret belongs in env.bl or app code.

The independent-VM rehearsal is research/service-world/check_namespaces.py. It
uses two immutable SDK selections, a provider-only implementation, a public
interface artifact, temporary private credentials and a host broker. It stops
its provider and removes the temporary directory in cleanup.

Native project startup owns imports and reuses unchanged bindings. Changed
provider source or interface data is checked again before relinking. In a warm realm, local providers are
vm.service members and close on realm retirement. A scope guardian also
cleans up after owner death. A later call can reacquire a crashed provider; an
interrupted call is never replayed. Embedded callers use
imports/activate! and imports/close! for an explicit scoped lifetime; cold VM
termination releases its whole state. Relinking and cleanup invalidate retained
function references. Calls read current memberships and verify code identity.

Admission covers a deliberately restricted source/ANF fragment using supported
pure core functions and explicit resource ports. Source, compiler generation
and executable identities are bound to the check. Unknown effects refuse
publication. Veritas exhausts the five boolean authorization gates; it does
not prove arbitrary programs or the whole runtime. Host ports, identity adapters,
compiler/analyzer and operator policy remain trusted components.

Network failures can still be unavailable or uncertain. The transport never
retries writes. Real mutation ports must own durable idempotency and receipts;
the counter here is isolated example data. This mechanism does not require a
consensus layer for a single authoritative provider.
