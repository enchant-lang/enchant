#+title: Local lock wakeups escape into a caller's mailbox after contention

* Observed

Backdesk commit150624a8 retains the failed native run15bfc190 under
=dossiers/evidence/admin-lot-3/owner-decisions/refused-model-15bfc190=.
The Proc event observer crashes in handle_info on
={:bl_local_lock_released, alias}= after using the runtime lock. The runtime
artifact is the immutable SDKvqy1 from sourcebcbf27ba; no provider write or
application message is involved.

* Cause and change

A waiter registers one monitor alias. Several successive holders can release
the key while that waiter cannot run. Each release sends a notification to
the still-live alias. Deactivation prevents future sends, but the old cleanup
consumed only one notification already queued after the selected wakeup.

Drain all queued wakeups for that exact alias after deleting the waiter and
deactivating its monitor. Preserve every application message and notification
belonging to another alias. Reentrancy, exact holder tickets, dead-holder
recovery and retry timing stay unchanged.

* Verification required

The new deterministic regression suspends a genuinely registered waiter,
releases the same real lock eight times, resumes it and inspects the mailbox.
It also checks unrelated messages and another alias are preserved. Run it
against the prior SDK to retain a counterexample, then the corrected runtime
with the existing generation-lock and Proc mutex suites. Backdesk's observer
and remaining admin/register/UI/browser qualifications remain required.
